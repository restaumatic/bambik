# Bambik

## Overview

A prototype PureScript library implementing **Profunctor User Interfaces** - a novel approach to declarative UI development. The key insight is that profunctors unify optics (data structure navigation) and arrows (data flow), making them ideal for composable UI development.

## Building

Do `export PATH=$PWD/node_modules/.bin:$PATH` and then `spago build` (tests: `spago test`). 

### PureScript custom compiler

Note the repo builds with the forked PureScript compiler pinned in `package.json` (variant row sugar `[ l :: T | r ]`, `.label` constructors — see doc/variant-sugar.md), so `npm install` first.

### Development loop - watch mode

When introducing code changes, keep `spago build -w` running in the background and read its output after each edit (~0.7s incremental) instead of one-shot `spago build`s per change — plain `spago build -w` covers library, tests, and the demos. Caveats: spago -w reads stdin and dies on EOF, so keep stdin open (never `</dev/null`); run only one watcher over the shared `output/` at a time. Parallel subagents sharing the repo must serialize compiles (`flock <lockfile> spago build`) — and when a serialized build fails, check the per-module `Compiling` lines for *whose* module failed before assuming it's yours. It's recommended to use git workspaces in such cases.

`npm run dev` serves **every** demo from one server at `http://127.0.0.1:1234/bambik/demo/`, in the same folder layout the deploy scps to the remote host — so a local URL matches its erykciepiela.xyz counterpart path-for-path (`/bambik/demo/7guis/counter/`), and the root landing page (demo/index.html) links the three sets. Narrow the bundling to what you're working on by name or set: `npm run dev counter cells`, `npm run dev nguis`. Auto-rebuild and browser auto-reload throughout (~2s per edit; scripts/dev.mjs — mtime-polling watcher over src/ and demo/, spago incremental build, one esbuild watch context per demo, reload broadcast over an SSE endpoint at `/bambik/demo/esbuild` using esbuild's own protocol, injected via the bundle banner so demo pages need no dev-only markup). Polling rather than `fs.watch`: inotify costs an instance per directory and Node hits its per-process ceiling well before the ~40 source dirs here, while `recursive: true` silently delivers no events at all on ext4. Runtime emission trace: set `window.__bambikTrace = true` (or `localStorage.setItem("bambik-trace", "true")`) in the browser console to log every propagation decision — stage-to-stage flow, `looped` re-feeds/swallowed echoes, and gate-withheld emissions with the sibling fields they wait for. Independent of the trace flag, every knowledge gate carries a **starvation watchdog**: a gate that withholds and is never fed within 3s prints one `console.warn` naming the gate and (for the record merges) the exact missing fields, with the fix (`seeded`/`announce`, or the seed argument of `feedback`/`folding`/`unfolding`) — so an unprimed gate is a named failure, not a blank screen (and an unprimed *entry* is now a compile error: `body` demands input `{}`) (browser-only; opt out with `window.__bambikNoWarn = true`).

Verification stack: `spago test` (value-level law tests over probes — merge units, gating, exactness, the trace quartet); `npm run smoke` (scripts/smoke/ — the committed headless-Chrome CDP harness: serves the repo, launches an isolated throwaway Chrome, runs scripts/smoke/tests/*.mjs; this is where the **carrier-only laws** are tested — the container action's keyed reconciliation/identity-follows-key in the real DOM, the gather gate on a live page (potluck) — plus per-demo smokes (including order-form, demo/1's Aff load → variant-pane → summary-tap walk); the value-level `Acting` laws (empty announces `[]`, singleton retraction, gather gate, keyed retention) run in `spago test` on `PUI Effect` probes; bundle the demos first, filter with `npm run smoke -- <name>`); `npm run api-docs` generates the browsable API reference into `generated-docs/md/` (gitignored) from the module headers — the single source of truth for combinator contracts.

## Building & Deploying Demos

1. Verify the forked compiler: `node_modules/.bin/purs --version` must report `0.15.16 [development build ...]`; if it shows stock `0.15.15`, run `npm install` (stock purs fails with "Module Prim.Variant was not found").
2. Bundle for deploy: `npm run bundle-demos` (minified, all demos; `node scripts/bundle.mjs <name|set>` for a subset) — use `npm run dev` for watch mode, not for deploys. **Every** demo is a named module (`OrderForm`, `Counter`, `Cells`, `TodoMvc`, ...) entered at its own function (`orderForm`, `counter`, `cells`, `todoMvc`, ...) — no module is `Main`, so they all compile together under one plain `spago build` — and each bundles from the shared registry in **scripts/demos.mjs** (the single source of truth for directory + module + entry, shared with the dev server), which synthesizes the esbuild entry per demo because `spago bundle-app` can only call `Main.main`.
3. Deploy: `npm run deploy-demos` — scps demo/index.html and the three set directories to host `xyz` (root@erykciepiela.xyz, see `~/.ssh/config`) at `/var/www/html/bambik/demo/`.
4. Verify: `http://erykciepiela.xyz/bambik/demo/<d>/` returns 200 (plain HTTP only).

## Architecture

### Core Type

```purescript
newtype PUI m i o = PUI (m { toUser :: i -> Effect Unit, fromUser :: (o -> Effect Unit) -> Effect Unit })
```

- `i` - input type (data model to display)
- `o` - output type (data model to capture)
- `toUser` - pushes model updates to UI
- `fromUser` - captures user interactions

  - the collection lives one level up, in **`src/Data/Profunctor/Acting.purs`** (module `Data.Profunctor.Acting` — beside `Row/`, not under it: rows are the finitary μ-free fragment of the container grammar, `Array = μx. 1 + a×x` is one `μ` later). `class Profunctor p <= Acting p where actedBy :: Ord k => (a -> k) -> p a b -> p (Array a) (Array b)` (the minimal carrier primitive) with the vocabulary form `acted @l :: Strong p => Cons l k ra a => Cons l k rb b => Lacks l rb => Ord k => p {|a} {|rb} -> p (Array {|a}) (Array {|b})` (like `edits`, the element's output row **excludes the key** — re-attached from the input row via the Strong state channel, so identity is unforgeable) — the **container action** (Tambara for `Array`, generated by `Strong`+`Choice`+μ), keyed by the row's **materialized identity field** (the element is a data-model row; rows carry their identity; `Ord k` is the reconciler's Map-indexing requirement — identity semantics remain equality; keys must be unique, never rendered). Laws in the header: **empty** (fed `[]` emits `[]` — announcing product-output unit; nothing at registration), **singleton retraction** (yanking at the container), **gather gate** (`Array b` withheld until every element spoke, retain-last thereafter), **identity-follows-key** (stateful carriers). The module holds only the **pure algebra** — the class, `instance Acting (->)` (`actedBy _ = map` — laws value-testable), and `optioned`; the carrier machinery lives with the carriers, exactly like the merge instances: **`PUI.purs`** carries `class Hosting m node | m -> node` (what a stateful carrier contributes — instantiate one element widget at runtime + placement: detach a leaver, restack survivors), the placement-free `Hosting Effect` instance (the probe carrier the `spago test` laws run on), the shared keyed reconciler, the one **generic** `instance Hosting m node => Acting (PUI m)`, and the two other collection combinators, all `Hosting`-generic: `foreach @l :: Cons l k r a => Ord k => PUI m {|a} o -> PUI m (Array {|a}) o` (the collapsed/sum-flavored form — **keyed and retaining** reconciliation, matched elements re-fed in place, nodes moved with their keys; forwards each element emission onto the shared channel, ungated, silent on empty; written trailing in a container ocular, `ul $ item # foreach @"id"`) and `edits @l :: Cons l k r a => Lacks l r => Ord k => PUI m {|a} {|r} -> PUI m (Array {|a}) (Array {|a})` (the **collection editor** — element emissions folded back in by key, whole array emitted **immediately**, input-primed: the retained fed array supplies unedited slots; the key is a **label**, not a function, and the element's output row **excludes** it — the carrier re-attaches each emission's key as the edit's return address, so an element structurally cannot change its key, and the old `# completed`-the-id-through convention dissolves — the element widens its input instead, `merge # widenRecordInput # edits @"id"`). The **keyed-input members** complete the direction square — their input is the runtime variant `{ key, value }` (one case at a time, the tag arrives in the input, so no key function; `Ord k` tags): `dispatched :: Ord k => PUI m a b -> PUI m { key :: k, value :: a } { key :: k, value :: b }` (+→+ — an unknown key instantiates a new case, a known key re-feeds exactly its instance, emissions leave tagged; the targeted-update/stream direction, no whole-array re-feed) and `accumulated :: Ord k => PUI m a a -> PUI m { key :: k, value :: a } (Array a)` (+→× — the keyed Mealy: grows per new key in first-appearance order, updates known slots, emits the whole array immediately, input-primed; the board/ledger shape); the +-members never detach/restack (absence of a key is no signal — removal/ordering stay array-level concerns upstream). Key forms encode the key's ontology: a **label `@l`** on the ×-members (identity = a materialized model field; in `edits` the output row excludes it and the carrier re-attaches it), the **`{ key, value }` envelope** on the +-members (identity = the structural tag, arriving in the input). The five divide the ground by input (everything at once → ×; one entity at a time → +) and output — individual event → `foreach`/`dispatched`; aggregate as joint decision (emission-primed gather) → `acted`; aggregate as running state (input-primed, immediate) → `edits`/`accumulated`; comparison table in `PUI.purs`'s container-action section. **`PUI.Web`** carries `instance Hosting Web Node` (DOM placement — `appendChild` moves nodes, so identity follows the key). `optioned` derives the `Maybe = 1 + a` action via the Array embedding. Design note: doc/collections-profunctor-algebra.md.
  - **`Row.purs`** (module `Data.Profunctor.Row`) — the shared floor: the row-constraint vocabulary (`InclusiveRows`/`ExclusiveRows` + the runtime-evidence duals `DispatchableVariants`/`MergeableRecords` with `exactRow`, bundled into the per-side classes `SharedRecordInputs`/`SharedVariantOutputs`/`OwnedVariantInputs`/`OwnedRecordOutputs` — sharing is inclusive, responsibility is exclusive, evidence only on owned sides — so each merge signature is two words, one per side; the owned sides also carry the `DisjointLabels` detector, which turns a duplicated label into a custom compile error naming the label — doc/type-errors.md #2) + the two `dimap`-only widening reshapings (`widenRecordInput`/`widenVariantOutput`) the `PUI` merge instances build on — `widenRecordInput` is **library plumbing, not vocabulary**: it is deliberately not re-exported from `PUI`, because record **subsumption is baked into the stages that read a row** (`tapped`/`displayed`/`updates`/`every`/`edits`/`acted`, plus `completed`), so a demo states each business function's exact footprint as a closed row and never coerces at the call site. It is *not* baked into `foreach` (the element row is inferred from the array), `provided` (the pane is fed the payload) or `onCase` (a case payload is pinned by its consumer as often as by its emitter) — **rows are read narrow, payloads are exact**; doc/no-nominal-types-in-ui.md states the adopted design rule (no nominal types in UI), doc/experiment-ad-hoc-rows.md records the measurements behind it.
  - **`Row/Example.purs`** — a phantom carrier with label-indexed widget signatures; **`test/Main.purs`** — value-level `(->)` tests (`focusRecord`/`property`/`recordToCase`) plus merge unit laws, gating, and the trace quartet and its row forms (`unfirst`/`unleft`/`coresolve`/`coretain`/`looped`/`iterate`/`feedback`/`folding`/`unfolding`) on the `PUI` carrier via a probe harness; **`test/HelloShutterReel.purs`**/**`BusinessOptics.purs`**/**`RestaurantReel.purs`**/**`EntityEventExample.purs`** — `Shutter`/`Reel` as business optics.

### Composition Patterns

- `Semigroupoid.do` (qualified-do) - Data flow pipelines
- `RecordToRecord.do` / `RecordToVariant.do` / `VariantToVariant.do` / `VariantToRecord.do` (qualified-do) - the four row merges
- label-indexed components - every MDC component is a citizen of one direction (`filledTextField @l` ×→×, `button @l` ×→+, `snackbar @l` +→×), so pipeline stages are written directly from components; `field`/`focusRecord` nest sub-composites into larger aggregates
- variant editing - **record-shaped editor state**: the model keeps the variant, the editor keeps every payload; `dimap` brackets the variant in (a state function seeding absent payloads) and out (a projection on the selection), around `looped Semigroupoid.do { selection component # completed; payload panes }` — each pane a payload-typed editor stage `# provided # lcmap <paneOf> # updates <setPane>`, shown by the presence of its `Maybe` payload; consistency via the self-trace re-broadcast; unit-payload variants need only the bracket around one selection component
- conditional visibility - always a named `Maybe`-valued projection + `provided` (never an in-UI predicate): conditional *data* (a pane whose content only exists sometimes) → `pane # provided # lcmap <maybeOf>`; conditional *mode of a live editor* inside a `looped` ensemble → a payload pane as above. `clWhen` stays predicate-driven — it toggles a class (styling), not visibility
- `tapped` - live views as pipeline stages (slider readouts, summary lines, data tables): display every emission flowing through, pass it on; the read function is closed at its own footprint (`tapped` subsumes)

### Separation of Concerns

- **Business Logic** - Row-shaped models, structural throughout: **no nominal types in UI** (the design rule, doc/no-nominal-types-in-ui.md) — a view-model type is one-off and specific to its UI, so it earns no name: UI code declares no `data`/`newtype`/`type` synonyms and writes anonymous Record rows (all-at-once) and Variant rows (one-at-a-time) in place, `{}` for unit payloads; role names live on seed *values* (`plannedTrip`, `tenSecondFreshTimer`), not on types; nominal types belong only below the UI, where recursion (cells' `Expr` AST — rows can't express μ) or an ecosystem API (`Aff`, `Either`, `Milliseconds` in `delay`) demands them, entering the UI only through business functions that project them into rows — plus plain functions and Aff actions (demo/1/OrderForm.purs); business optics (Shutter/Reel) where state/loop semantics are needed (test/BusinessOptics.purs). Two handler disciplines: **exact footprints** — an `updates` handler's row is exactly what it reads∪writes (one `match` shares one patch row, so group buttons into stages by patch row, as stopwatch does); a handler that reads *nothing* is not a transformer but a **constant patch** (`beginTiming :: { running :: Boolean }`, call site `const (const beginTiming)`) or, at a bare button whose row nothing else pins, a `{} -> patch` builder fed to the button (`button # lcmap reset # updates (match { clicked: const })` — the button is fed its patch and replays it). **Business emissions carry bare data, never UI copy** — toast/banner text lives in `PUI Web`-returning widget functions (`welcomeToast = snackbar # forCase @"registered" # lcmap (match …)` in signup-form; espresso-bar's `brewedToast`, demo/1's three toasts, inbox's `inboxZeroBanner`), while validation reasons/outcomes stay business payloads
- **Design System** - Oculars in Web.purs and MDC.purs
- **Composition** - UI elements compose orthogonally to the row combinators
