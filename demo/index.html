Code style

Comments are deliberately absent - code should read on its own. Imports are 100% explicit (including Prelude) - code is honest about its dependencies. Each listing is a complete standalone application, entered at its single exported function. The code is structured as one purely UI-related function followed by pure business functions and data. Each UI-related line leads with the visual concern with $ plumbing and trails with the data concern with # plumbing. Business literals never hide in UI code: a slider edits a bounded quantity { current, min, max, step } whose bounds are model data flowing from the seed (never widget config), and what legitimately stays config or seed content - tick periods, default payloads - is a named business definition (tickPeriod, gameStart - business language, never lifecycle words like initial or default), so UI code keeps only presentation. No nominal types in UI: view-model types are one-off and specific to this UI, so they earn no names - anonymous record and variant rows written in place, with no data, newtype, or type declarations in UI code. The code is compiled with a custom PureScript compiler with improved support for variants - anonymous sum types, dual to records: a variant type is written [ ok :: Int, err :: String ] the way a record is written { ok :: Int, err :: String }, and its cases are constructed with .ok 42.

Tracing

Every demo page runs with enabled tracing, so data propagation is logged to the browser console with [bambik] prefix.
