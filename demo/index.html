Code style

Every demo follows these rules. The skill's writing.md states them in full.

Modules

  • A view and a view model, with a one-way dependency:
    • the view exports one entry function and imports the design-system vocabulary and the view model;
    • the view model holds pure business functions and values and imports only domain modules (Prelude, data modules, Effect, Aff, Data.Variant.Case);
    • further modules are only a view model test, a stand-in server (crud) or packaged controls (order-dashboard).
  • The view determines the view model. With a typed hole for every imported value, the compiler reports each at a concrete type; those types are the view model's signatures. npm run check-determined enforces this.
  • Twins share one view model. A design-system switch is a view-only diff.
  • Tests are values. A view model test lists named claims (CounterViewModelTest).

Layout

  • No comments.
  • Explicit imports, Prelude included.
  • A line leads with what is seen, via $, and trails with data concerns, via #.
  • A decorator trails its element: checkbox @"Loyalty" … # tooltipWith loyaltyNote, never tooltip … $ checkbox ….
  • Two-space indentation; a closer returns to its opener's column.
  • A closer or # chain never starts a line, except a seed closer () # with seed) and the closer of a broken row.
  • A declared row or signature too long for its line takes one field per line.
  • Pipeline order: load, form, live summary, events, actions with their statuses, closed by the seed.
  • The entry is body $ …; the page supplies the surface.

Anchors

  • Every line names exactly one anchor:
    • a model field, as the type argument of an editor, selector or group: filledTextField @"First name" {}, group @"Customer" $ …;
    • a business case, as the type argument of an emitter, pane or status: button @"Submit order" {}, snackbar @"booked" bookedLine;
    • a copy function, as a display's positional argument: text balanceLine, text _.title;
    • nothing, for chrome: card, staticText "Hours".
  • A visible @"…" names a field or a case, nothing else. Titles and static texts are strings: topAppBar "Espresso Bar".
  • A leaf reads word, anchor, positional arguments. Its record holds only optional presentation: { icon: "person_add" }, { columns: 80, rows: 3 }.

Labels and copy

  • A label is its caption verbatim, punctuation, format hints and units included: filledTextField @"Start date (DD.MM.YYYY)" {}, sliderLive @"Amount (€)" {}.
  • No demo passes a caption config: a leaf states its copy once, as its label.
  • Options are one choice per case, joined by <+> in display order: choice @"one-way" <+> choice @"return".
  • A case label is read back with caseText, never restated in a match.
  • A display's text is a named copy function in the view model, whole line including glue: balanceLine :: { balance :: Number } -> String.
  • Static copy (a heading, a note) is a literal in the view: staticText "Hours".
  • Events and outcomes carry data, never copy: flight-booker's problems are reasons, phrased by problemLine.

Types and values

  • No data, newtype or type declarations in UI code.
  • A row holds records, variants, String, Number, Int and Array.
  • No Maybe in the model: selected :: [ none :: {}, picked :: { index :: Int } ].
  • No Boolean unless a Boolean editor edits it: status :: [ active :: {}, completed :: {} ].
  • The model row is declared once, where the model first appears: # looped @( counted :: Int ) # with freshCount.
  • A derived row is declared where it is introduced: a classifier's cases on its first pane, an action's outcome, a projection's element row.
  • A stored field is read with an accessor: _.messages.
  • Business values are model data: a slider edits { current, min, max, step } from the seed.
  • Constants have business names (tickPeriod, freshCount), never initial, default or seed.

Business functions

  • A signature is the compiler's hint verbatim: the row the stage is fed, closed. countLine :: { counted :: Int } -> String, never narrowed, never opened with a tail.
  • A handler updates the row it is given: increment m = m { counted = m.counted + 1 }.
  • A constant replaces the model only whole, in a fold: fold (const openingPosition).
  • Each event case has its own fold, opened by its status: snackbar @"Count" countedLine # fold increment.
  • A fold shows a status only where a real app would notify: a backend outcome, money moved, a destructive action. Direct manipulation folds silently: blankStatus @"Todo toggled" # fold toggleTodo.
  • An event with a payload of its own is # joined @l and handled by one record: toggleTodo :: { event :: Int, model :: … } -> ….
  • An action returns the model under its outcome case, folded by identity.
  • A business function takes one record; field names carry the roles: returnBetween { out, back }.

Wiring

  • Never import the ecosystem's Data.Profunctor; a reshaping rides a word's argument: foreach @l rowsOf, toCase @l payloadOf.
  • State lives in the model: no FFI stashes, window globals or hidden loop channels.
  • Stock components only; custom style only for data-driven graphics.

Compiler

  • A forked PureScript compiler adds variant sugar: a variant type is written [ ok :: Int, err :: String ] like a record type, and a case is built with .ok 42.

Tracing

Every demo page runs with enabled tracing, so data propagation is logged to the browser console with [bambik] prefix. The spatial half of the same picture is the browser's own accessibility tree (DevTools → Elements → Accessibility): every component stamps its label — name on editors, the case label as a button's accessible name, role="group" + the heading on labelled groups — so the tree reads as the model itself (groups are sub-records, editors are fields with their current values), and a starving gate's warning logs the missing fields' elements, clickable in the console.
